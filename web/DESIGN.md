# 播放室設計系統

變數在 `src/design/tokens.css`，元件在 `src/design/components.css`。版面只能引用變數，不能寫死顏色、字級、間距；要新按鈕先用現有元件，真的不夠再在這份文件加元件。

## 元件

### 按鈕 `.btn`

| 變體 | class | 用在 |
|---|---|---|
| 主要 | `.btn.btn--primary` | 一個畫面最多一顆：「挑一張來放」「在這裡聽」 |

| 狀態 | 樣子 |
|---|---|
| 預設 | 主要：棕褐底深字；次要：面色底骨白字 |

| 停用 | 透明度 `--dim`，游標禁止 |

### 分段切換 `.seg` + `.seg__opt`

一組互斥選項。外層 `role="radiogroup"` 加 `aria-label`，每顆 `role="radio"` 加 `aria-checked`；只有選中的那顆在 Tab 順序裡（`tabindex="0"`），方向鍵切換。選中＝骨白底深字，指上去＝棕褐底。加 `.seg--fill` 讓選項平分整列寬度。用在：時間範圍、房間時段。（現場燈光 2026-11-08 改成放歌時自動開，不再有切換鈕）

### 3D 上的字

**不在每段字後面墊方塊**，那會像貼紙。定點畫面（`.moment`、唱盤）的上緣和下緣各有一層由深到透明的暗部（`--scrim-strong`，各佔畫面高度 34%），像電影片頭字幕。

- 疊在 3D 上的字**只能放在畫面上緣或下緣**，不能放在畫面中間
- 字要貼著邊界（`--margin`），落在暗部最深的那一段
- `.on-scene` 只是標記「這段字疊在 3D 上」，方便檢查

### 排行榜 `.chart`

每列：名次（前三名用強調色）｜歌手照片 56px｜歌手名＋代表歌｜和全期比（▲ 上升與新進榜用強調色，▼ 下降用次要色）。右邊固定一張 4:5 的大照片，跟著滑鼠或鍵盤聚焦的那一列換；手機版不顯示大照片。

### 說明文字 `.note`

控制項旁邊的限制或說明（原本用在麥克風的隱私說明，麥克風 2026-11-08 已拿掉）。用 `aria-describedby` 綁到控制項上。

## 版面規則

- **定點區塊（`.moment`）必須透明**：它的工作就是讓後面的 3D 透出來。內容多的區塊才用實色底。
- 沒有 3D（瀏覽器不支援 WebGL）時，定點區塊要有 HTML 備案內容，不能只剩空白。

## 手機版版面規則（390／375 寬，給人看之前必過）

疊字、被擋、爆版都是 bug，不是「之後再調」。以下每條都對應過真的出過的問題。

1. **固定在畫面上的東西（`position: fixed`）一定要有底**：頂列、播放列、字幕這類會讓內容從底下捲過的層，要有 `--scrim-strong` 漸層或實色底（做法照 `.bar::before`）。沒有底就會跟捲上來的內文疊字。
2. **暫時的浮層要跟它的時機一起消失**：開場字幕、「直接進房間」這類只屬於某個階段的東西，離開那個階段（包含訪客自己捲走）就要馬上收，不能等動畫跑完。捲走的判斷不能只靠 `wheel`／`touchmove`，鍵盤、捲軸、錨點連結也會捲。
3. **底部固定層要讓出位置**：手機播放列橫跨底部 80px，任何貼底的按鈕、提示都放在它上方（`bottom: 108px + safe-area`），內容區底部留 `--dock-safe`。
4. **層級只用 `--z-*` 變數**：不要寫數字 z-index。新的浮層先想清楚它在誰上面、誰下面，再加變數。
5. **觸控沒有 hover**：不要把觸控的 `pointerdown` 當成「指著」（手指一碰、包括開始捲動就會觸發），點到什麼用點擊當下的座標直接算（3D 用 `room.hitAt()`）。
6. **不要用捲動距離挑東西**：手機一滑有慣性會飛過很多項，桌機滑鼠指著的也會跟捲動位置打架（CD 牆曾經抽出 A、字幕講 B）。挑選只有一個「選中的那個」：滑鼠指到就選、觸控點一下選（再點才執行）、「上一張／下一張」（`@media (pointer: coarse)`）與方向鍵一次換一個。畫面上亮起來的跟字幕講的永遠是同一個。
7. **不准橫向捲動**：`html, body { overflow-x: clip }` 只是保險，元素本身不能比畫面寬；負邊距要用 `calc(100% + 欄距)` 補回。
8. **按鈕列一律 `flex-wrap: wrap`**：兩三顆按鈕在 375 寬放不下時換行，不要擠壓或超出。
9. **看不見就不能點**：用 `opacity: 0` 藏起來的層，裡面每個子元素都要 `pointer-events: none`（子元素自己設了 `auto` 會穿透）。開場時頂列透明，時段鈕卻還點得到，而且蓋在「直接進房間」上面。
10. **3D 畫面裡的字也算疊字**：招牌、CD 封面這類 3D 裡的東西，跟 HTML 文字撞在一起，訪客看來一樣是疊在一起。手機鏡頭用 `phonePose()` 依寬高比微調（矮手機 375×667 另外處理），頁尾這種會把文字往上推的地方，加鏡頭點（`data-cam`）讓鏡頭跟著移動。腳本抓不到這類問題，一定要看截圖。
11. **第一眼的畫面最重要**：開場（還沒點擊）的畫面要跟其他段落一樣檢查。
12. **手機覆寫要寫在基本規則後面**：`@media (max-width: 900px) { .x { display: none } }` 跟 `.x { display: flex }` 權重一樣，寫在前面就被蓋掉、等於沒寫（「往下捲」提示就是這樣在手機上隱藏失敗）。
13. **載入中不能擋住內容**：3D 素材還沒載好時，文字照常可讀可捲；全畫面的「整理中…」暗場在手機網路下看起來就是卡死。
14. **不能只有按了按鈕才會動**：手機訪客多半直接往下滑，不會先按「進門」這類按鈕。捲到那一段該出現的東西（時間軸、鏡頭、內容）要靠捲動位置啟動。放映室時間軸就是因為要先按「撕下票根」才會畫，手機上捲了 7 個螢幕高都沒有內容。
15. **稽核 0 項不等於沒問題**：腳本只看網頁文字。3D 裡的字和圖（銀幕劇照、招牌、CD 封面）跟文字疊在一起它抓不到，「一直往下捲、畫面都不變」它也不會報。每張截圖都要用眼睛看。
16. **3D 裡的小目標，手機要有網頁版的選法**：書背、CD 這種畫面上只有幾 px 寬的東西，手指點不準（放映室書背、開場點 A 放 B 都是這樣出事的）。手機要給一排可以左右滑、夠大的網頁按鈕（海報條），點了再接回 3D 的動畫；點擊一律用手指落點直接算（`hitAt`），不要用「光／游標剛好在哪」代替。
17. **按鈕不能按了沒反應**：狀態已經是結果（例如那部已經在放）時，也要給回應——帶去結果所在的地方，不要默默 return。
18. **任何元素都不能把手機版面撐寬**：一撐寬手機就把整頁縮小，3D 畫面看起來被切掉、歪一邊（放映室被海報條撐到 776px）。每頁的 `html, body` 都要 `overflow-x: clip`；放在 flex 裡、內含長列（海報條、表格）的區塊要 `min-width: 0`。驗收腳本每張都要記 `innerWidth`，變了就是被撐寬。
19. **大面積可點的層要關掉點擊高亮**：整個畫面都能點的層（開場對話）要 `-webkit-tap-highlight-color: transparent`，不然手機每點一下整片閃藍。

**驗收**：用 Aside 跑——先 `npm run dev`，再執行 `web/.aside/run-mobile.sh`（結果在 `web/.aside/out/mobile/`，含截圖）。沒有 Aside 時才用 headless 備援：`npm run build` 後 `npm run audit:mobile`（Claude Code 沙盒裡加 `AUDIT_SINGLE_PROCESS=1`）。它在 390×844、375×667 兩種寬度，先檢查開場畫面，再逐段截圖，列出 `OVERLAP`（文字互疊）、`TRUNCATED`（文字被截到剩不到四成）、`COVER`（文字被蓋）、`OFFSCREEN`（超出左右）、`UNDER-BAR`（捲進沒底色的頂列）、`HSCROLL`（橫向捲動），有任何一項就 exit 1。結果與截圖在 `$TMPDIR/mobile-audit/`。改了版面或給人看之前都要跑到 0 項，截圖也要用眼睛看過一次（腳本抓不到 3D 畫面裡的問題）。

**順暢與觸控**：`run-mobile.sh` 裡的 `touch`（手機）與 `desk-hover`（桌機滑鼠）兩支；headless 備援是 `npm run audit:mobile-perf`。CPU 降速 4 倍，用觸控手勢滑到底：第一下要跳過開場、不能卡住、滑動中長任務不超過 1 秒；CD 牆點過再滑，發光那張要跟字幕同一張；「下一張」1 秒內有反應。沙盒的模擬 GPU 不能平行編 shader，載入時間只列出不判定，要看真手機。

## 規則

- 標題在任何寬度都不超過兩行
- 不用：漸層、靜止時的陰影、細分隔線、小標籤、等寬字、01／02 編號、毛玻璃、一排相同卡片
- 按鈕方角、單一填色、高度至少 48px
- 中英文之間空一格（`spaceMixed()` 自動處理）
- 動態只動 `transform`、`opacity`、`clip-path`，每一個都要有 `prefers-reduced-motion` 的版本
